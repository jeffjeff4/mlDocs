MinHash & LSH

大规模数据相似度检测的利器

📊 MinHash：集合相似度的签名

核心思想

MinHash通过哈希函数将集合映射到固定大小的签名，使得两个集合的Jaccard相似度可以通过签名快速估计。

Jaccard相似度

J(A, B) = |A ∩ B| / |A ∪ B|

即：交集大小 ÷ 并集大小

MinHash算法步骤

  • 准备 k 个独立的哈希函数 h₁, h₂, ..., hₖ
  • 对集合中每个元素应用所有哈希函数
  • 对每个哈希函数，取所有元素哈希值的最小值
  • 这 k 个最小值组成MinHash签名
关键性质：两个集合MinHash签名中相同位置值相等的概率 = 它们的Jaccard相似度

🔍 LSH：快速找到相似对

核心思想

LSH将MinHash签名分成多个bands，相似的项在至少一个band中完全匹配的概率很高，从而被分到同一个桶中。

LSH参数

  • b (bands)：将签名分成多少段
  • r (rows)：每段包含多少个哈希值
  • 签名总长度：b × r

候选对概率

P(成为候选对) ≈ 1 - (1 - s^r)^b

其中 s 是Jaccard相似度

调参策略：
  • 增加 b：提高召回率（找到更多相似对）
  • 增加 r：提高精确率（减少误报）

📐 数学原理深度解析

1. MinHash的数学证明

核心定理

为什么 P(sigA[i] = sigB[i]) = J(A,B)？

设定：

  • 集合 A 和 B
  • 一个随机哈希函数 h，将元素随机映射到整数
  • minA = min{h(x) | x ∈ A}
  • minB = min{h(x) | x ∈ B}

关键观察

考虑并集 A ∪ B 中的所有元素。在随机哈希下，每个元素都有相等的概率成为"最小哈希值"。

情况分析：

minA = minB 当且仅当 A ∪ B 中哈希值最小的元素同时属于 A ∩ B

为什么？
• 如果最小元素在 A ∩ B 中 → minA = minB = h(该元素) ✓
• 如果最小元素只在 A 中 → minA < minB ✗
• 如果最小元素只在 B 中 → minB < minA ✗
P(minA = minB) = P(最小元素 ∈ A ∩ B) = |A ∩ B| / |A ∪ B| = J(A,B)
直观理解：
想象把 A ∪ B 的所有元素随机洗牌，然后一个个翻开：
  • 翻到第一个元素时，它在交集中的概率 = |A ∩ B| / |A ∪ B|
  • 如果在交集中，A 和 B 都会选它作为最小值 → 签名相同
  • 如果不在交集中，A 和 B 会选到不同的最小值 → 签名不同

2. LSH的概率调控原理

核心问题

为什么可以通过 b 和 r 调节 precision/recall？

设定：

  • 签名长度 = b × r
  • 将签名分成 b 个 bands，每个 band 有 r 行
  • 两个集合的相似度为 s

步骤1：单个band的匹配概率

在一个 band 内，两个签名完全匹配（r 个位置全部相同）的概率：

P(一个band完全匹配) = sr

因为每个位置匹配的概率都是 s（MinHash性质），r 个位置独立匹配的概率就是 sr。

具体例子：
如果相似度 s = 0.8，band长度 r = 4
• P(band匹配) = 0.84 = 0.4096

如果相似度 s = 0.3，band长度 r = 4
• P(band匹配) = 0.34 = 0.0081

✓ 高相似度和低相似度的概率差距被放大了！

步骤2：至少一个band匹配的概率

我们关心的是：至少有一个band匹配（成为候选对）

P(至少一个band匹配) = 1 - P(所有bands都不匹配)
= 1 - (1 - sr)b

这就是候选对概率的公式！

S曲线分析

函数 f(s) = 1 - (1 - sr)b 形成一个 S 形曲线，有一个"阈值"：

阈值 t ≈ (1/b)1/r
阈值附近的陡峭变化：
• s < t 时，P(候选对) 快速下降 → 不相似的很难成为候选对
• s > t 时，P(候选对) 快速上升 → 相似的很容易成为候选对
• 在阈值处，曲线最陡峭 → 精确"切一刀"

参数调控效果

增大 r（每个band更长）

效果：sr 对 s 更敏感

例：s = 0.6

  • r = 2: 0.62 = 0.36
  • r = 4: 0.64 = 0.13
  • r = 8: 0.68 = 0.017
✓ 提高 Precision
更严格的匹配要求，减少假阳性

⚠ 降低 Recall
可能漏掉一些相似对
增大 b（更多bands）

效果：更多"机会"匹配上

例：单band匹配率 p = 0.2

  • b = 2: 1-(1-0.2)2 = 0.36
  • b = 5: 1-(1-0.2)5 = 0.67
  • b = 10: 1-(1-0.2)10 = 0.89
✓ 提高 Recall
找到更多相似对

⚠ 降低 Precision
更多假阳性（不太相似也可能匹配）

具体数值例子

假设相似度 s = 0.6，比较不同配置：

配置1：b = 2, r = 4 (高precision)

单band匹配概率 = 0.64 = 0.1296
候选对概率 = 1 - (1 - 0.1296)2 = 0.243

只有24.3%的概率成为候选对，但假阳性少

配置2：b = 4, r = 2 (高recall)

单band匹配概率 = 0.62 = 0.36
候选对概率 = 1 - (1 - 0.36)4 = 0.832

83.2%的概率成为候选对，很难漏掉相似对

配置3：b = 10, r = 5 (平衡)

单band匹配概率 = 0.65 = 0.078
候选对概率 = 1 - (1 - 0.078)10 = 0.547

54.7%的概率，在precision和recall之间取得平衡

实际应用中的权衡决策

  • 去重场景：需要高recall，不能漏掉重复 → 增大b，减小r
  • 精确搜索：需要高precision，减少计算量 → 增大r，减小b
  • 通用场景：选择让阈值 t = (1/b)1/r 接近你关心的相似度
S曲线的直觉：
想象一个考试系统：
• r 是题目数量：题目越多，及格和不及格的区分越明显
• b 是考试次数：考多次试，给更多机会通过

调节这两个参数，就能精确控制在什么相似度"切一刀"！
💡 数学设计的精妙之处：
用简单的概率乘法和补集运算，就实现了灵活的阈值控制。这个优雅的公式背后，是对独立事件概率和组合优化的深刻理解。
